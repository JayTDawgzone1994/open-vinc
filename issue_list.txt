# Axon Bus Verification Issues List

我在 `test_module.cpp` 內加入 `AxonBus` 的訂閱 (subscribe) 與發布 (publish) 測試功能後，在編譯與驗證過程中遇到了以下問題：

## 1. `AxonBus` 核心連結錯誤 (Linker Errors)
在編譯 `stem_shell` 連結時，出現了以下嚴重的 `undefined reference` 錯誤：
* **缺少建構子實作**：`vinc::AxonBus::AxonBus()` 只有在 `.hpp` 中宣告，但在 `.cpp` 內沒有實作，導致連結失敗。
* **Template 實作位置錯誤 (`LockFreeObjectPool`)**：`LockFreeObjectPool` 的一些模板成員函數（例如 `acquire_raw_node` 和 `Deleter::operator()`）找不到實作。這通常是因為模板實作被放在了 `.cpp` 檔中，而不是在標頭檔 `.hpp` 裡，導致其他編譯單元無法展開模板。

## 2. `make_message` 模板實作問題
這是一個架構問題：`AxonBus::make_message<DerivedMsg, Args...>` 是一個模板函數，但它的實作被寫在了 `axon_bus.cpp` 中。這違反了 C++ 模板的展開規則，除非在 `.cpp` 內顯式實例化所有可能的 Message，否則一旦有外部模組（像 `test_module`）去呼叫它，必然會產生 `undefined reference` 的錯誤。

## 3. Ribosome 生成的 Message 標頭檔皆為空檔案 (0 Bytes)
`ribosome` 在執行生成器 (generate_messages target) 時，雖然宣稱有 parse 到訊息檔案，但最後吐出來的 `.hpp` 實體檔案內容大小全部都是 **0 bytes**。這導致沒有實際的 Message struct 可以用來發送，測試時只能在模組裡手刻一個 `DummyMsg` 來繼承 `BaseMessage` 進行測試。

## 4. 發動機 (Engine) 沒有被主程式喚醒
在原本的架構中，`AxonBus` 的 Worker Threads 必須依賴 `AxonBus::get().start_engine()` 來啟動，但我檢查過 `stem_shell.cpp` 與主程式進入點，發現並沒有任何地方呼叫這個啟動函數。因此如果不手動呼叫它，Bus 的任務佇列就算收到訊息也不會有執行緒去處理。我目前在 `test_module` 的建構子中暫時補上了呼叫，但這應該要移到系統初始化的生命週期中。
